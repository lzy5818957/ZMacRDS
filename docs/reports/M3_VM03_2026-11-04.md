# VM03 同一 RDP 入口双用户实验

日期：2026-11-04（宿主 PST）。这是 M3 的受控实验，不是完整 M3 发布验收。

## 已验证结果

同一 VM03、同一 `127.0.0.1:3390` 入口，macOS Windows App 同时以 A、B 的独立测试凭据连接，各自获得对应 UID 的真实桌面。已验证两侧独立内容、后台输入、A 重连保留原编辑器/文档且 B 持续工作，以及 A 代理短暂停顿只关闭 A 的连接。没有通过不同端口伪装多用户。

随后使用两个独立的 RDP 自动客户端，服务端测得两条已认证 GUI 连接连续重叠 **1,830.000 秒（30 分 30 秒）**。A、B 各完成 100 轮，两个编辑器均收到了自己账号的全部文本，期间没有出现另一账号的负载文字、桌面标记或输入标记。宿主该时段的电源日志没有 Sleep、Wake 或 DarkWake 事件。

接收端按 VM 单调时钟记录：A 的控制权从 29594200 至 31424209 ms，B 从 29594209 至 31424209 ms。两条连接释放后，确认入口仅剩监听套接字，再分别尝试 A 用户名配 B 口令、B 用户名配 A 口令；两次都明确拒绝且零图像。加上账号使用期间的重复登录和两次口令错配，共五项认证负向检查通过。

## 路由与权限

root 只执行启动阶段：读取 root 持有的私有配置、创建每 UID 的本地监听器并启动 relay。网络入口随后永久降为 VM 管理账号的 UID 501，两个 relay 分别运行于 UID 502、503。GUI 故障/恢复组 PID 为 17253 / 17254 / 17255，持续工作负载组为 18374 / 18376 / 18377。进程和监听证据保留在结果目录。

每个 RDP 连接拥有自己的认证状态、输入、画面和 UID 控制权。相同账号只允许一个控制端；认证失败不会清除其他连接的授权。relay 校验入口的内核 UID，再以自身 UID 接入本账号 GUI 代理；完整会话身份及 lease 仍由 M2 桥接协议校验。连接无法通过提交一个数字 UID 直接选择桌面。

配置中的网络密码是分别生成的随机测试口令，不是 macOS 账号密码。Windows App 使用 Ask when required，未保存密码。短期测试证书的 SHA-256 为：

```text
34:A5:A6:E1:5C:86:0C:35:AE:A5:15:24:95:7E:6D:32:50:46:28:D3:D1:87:97:A5:5D:CE:A0:3B:F9:A2:8E:EF
```

用户已授权本轮核对后的证书例外，未勾选 Always trust、未导入系统信任。自动客户端验证证书名称、时间和签名，并额外比较完整 DER；没有使用跳过验证的连接方式。

## 功能和边界检查

| 检查 | 结果与证据 |
| --- | --- |
| 同入口并发 | Windows App A/B 的 PC 地址均为 `127.0.0.1:3390`；服务端同时存在两条已认证连接，对应 UID 502/503，实际桌面标记不同 |
| 真实中文输入 | Windows App Scancode 配合服务端简体拼音：A 文档由“你好”继续输入为“你好世界”，组合回调累计 11 次 |
| B 后台输入 | 控制台 UID 为 502 时，B 的编辑器收到 `b-background-fixed`，GUI UID 仍为 503，未切换宿主控制台账号 |
| A 断线重连 | A 连接 3 正常断开，连接 6 重新进入同一审计会话；编辑器 PID 16397、随机数 3920732162 和“你好世界”保留 |
| B 不受 A 重连影响 | B 连接 5 未断开，同一编辑器 PID 16535 收到 `b-during-a-disconnect` |
| 单用户代理停顿 | SIGSTOP A 测试代理 4 秒后恢复；A 连接 6 被单独关闭，B 连接 5 保留并收到 `b-survives-a-stall`；入口无持续忙循环 |
| 重复登录 A | 正确 A 凭据的第二控制端收到明确 `ServerDeniedConnection`，图像更新为 0，原 A/B 连接保留 |
| 错误/交叉口令 | 账号使用中及释放后，A 用户名+B 口令、B 用户名+A 口令均收到明确拒绝、零图像；正式负载服务端拒绝记录为零帧/零输入 |
| 端口占用启动失败 | 第二次启动返回非零状态，新增 relay 退出；仅原入口和原两个 relay 存活，现有连接保持 |
| 自动输入送达 | 第二轮有节奏的脚本，两侧各 100 个唯一中英文完整内容、100 次目标坐标拖动、100 次编辑器点击；按接收窗口事件日志核验 |
| 缺失凭据 | 独立画面门槛有单元测试；本轮未单独完成网络层缺失 ClientInfo 凭据用例 |

最终打包的入口另在同一 VM 实测：PID 19740 完成降权（UID 501），其两个子进程 19742、19743 分别为 UID 502、503。包内客户端同时连入，两路各持续 12.005 秒、解码 12 个不同的桌面计数、发送 8 个操作。同一批编辑器 PID 18348、18361 分别收到完整的 `A-final-中文`、`B-final-中文`。该构建亦通过前述账号使用中和空闲时的五项认证负向检查。

在最终构建上，两账号的编辑器均从自己的连接收到 Shift、Control、Option、Command 配合字母键的实际事件（标志分别为 `0x20000`、`0x40000`、`0x80000`、`0x100000`）。让 A 保持 Shift 按下后，直接终止 A 客户端；此时 B 始终在线，随后收到的普通字母键修饰标志为 0。A 再次连接后回到原编辑器 PID 18348，其第一个普通字母键同样为 0。B 的这次控制权完整覆盖了 A 的异常断开和重连，持续 45.000 秒。完整的双平台组合键矩阵仍待测试。

最后用 macOS Windows App 重连到同一份最终服务端：连接 11 和 12 同时建立，直接在 A 窗口看见 UID 502、B 窗口看见 UID 503；两条 GUI 控制权重叠 40.512 秒。该结果与上表的 30 分 30 秒自动客户端长测分别记录。

输入自动化只操作项目自带的合成测试窗口，未操作个人工作资料。早期集中输入组的编辑器 PID 为 17450/17465，前缀 A29/B29。持续工作负载组使用 PID 18348/18361、窗口 2242/2244，标记从 `A30-000-中文` 到 `A30-099-中文`、从 `B30-000-中文` 到 `B30-099-中文`；两侧每 18 秒各进行一轮。

## 发现并修复的问题

第一轮切换 VM 控制台账号后，某个桥接流关闭。桥接层向 IronRDP 返回可重试错误，但该库会立即再次读取，形成忙循环，导致另一用户的画面和输入也停止。该轮失败记录保留，不能计入稳定性通过。

修复为：终止的桥接流返回 `Ok(None)`，让协议库关闭对应连接。新增回归测试同时覆盖显式关闭和发送端消失。修复后实际暂停 A 代理，A 断开而 B 继续刷新和输入，验证了跨用户影响已消除。

最初的自动脚本把整个拖动在同一瞬间发送；内容输入成功，但未收到目标测试窗口的拖动事件，所以没有把“事件已发送”算作拖动通过。随后增加窗口激活点击及鼠标转换之间的间隔，接收日志出现完整的按下→位移→释放，并重跑各 100 轮。

宿主机中途发生休眠。原自动连接唤醒后继续收帧，但这段不计为连续 30 分钟。另起两条连接重跑，并添加限时防空闲休眠措施；不会更改永久电源设置。

另一次把 100 轮操作集中在前几分钟时，VM 的前台显示器在后续闲置期间熄屏。A 捕获停止，连接 14 在约 841 秒断开；后台 B 连接 13 继续返回自己的像素。唤醒后直接回到 A 测试桌面，无需输入密码，因此不把此例记为密码锁屏验收。正式负载把操作分布在整个时段，并在 VM 使用限时显示保持；不能据此声称默认空闲/熄屏状态也会持续出图。

## 证据和复跑

本机证据目录为 `build/vm03-results/m3-27/`（0700、Git 忽略），包括修复前日志、Windows App 恢复状态、服务端审计、接收事件、自动客户端记录、测试二进制与源码哈希。运行凭据仅在私有测试配置中，不写入报告或版本库；没有导出桌面像素文件。

持续负载验收汇总在 `verification.json`，最终构建的检查在 `final-smoke/`、`final-modifiers/verify.json`、`server-final.jsonl`。14 项 Rust 测试、28 项 Python 测试均通过；项目两个 Rust 包的 Clippy 与格式检查通过。最终服务端收到 SIGTERM 后，入口、两个 relay、私有套接字目录均已退出或移除；已核实 VM 与宿主均无 3390 监听。两个合成 GUI 代理与编辑器退出，VM03 仍运行，Windows App 保留 A/B 两个配置供复跑。

`tools/m3-verify.py` 从 manifest 读取已完成的客户端/代理/编辑器日志，验证：同一服务器启动周期内两条连接的重叠时间、正确新像素、完整控制权生命周期、输入标签、每轮文本、实际拖动轨迹和点击，以及认证负向结果。两个顺序执行的成功日志不能被算作并发通过。

操作和配置格式见 [M3 操作单](../M3_TEST.md)。

## 验收范围

本轮只证明 VM03 既有 A/B 会话的同入口双用户实验能力。Windows App 的两条连接来自同一宿主；长时像素自动验证使用两个独立 IronRDP 客户端进程，不能替代两台实体客户端的完整 C-MM 工作负载，也不能据此宣称 Windows `mstsc` 已兼容。

未完成：Windows/Windows、Windows/Mac、跨平台恢复、两用户 Codex 工作负载、完整修饰键/慢客户端/网络黑洞/锁屏与撤权矩阵、系统认证和 NLA、代理自动重新注册、冷启动创建 GUI 会话、多屏/动态分辨率、32 人容量与生产安全审查。完整 M2、M3、M4 均未标为通过。
