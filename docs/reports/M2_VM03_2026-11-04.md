## 发现与修复

1. 初始动态图的红蓝通道顺序不符线上的 BGRA 布局，已修正；真实桌面按 BGRA 传输。
2. macOS Unix socket 默认缓冲使大帧不能及时传完。代理提高有界发送缓冲，并仍只保留一个待发送包；1920×1200 帧和 3 秒心跳检查随后通过。
3. IronRDP 0.13.0 将绝对鼠标按钮包转换成单个按钮事件，丢失包内坐标。Windows App 只发送该按钮包时，点击错误地落在旧位置。仓库内的[小范围补丁](../../vendor/ironrdp-server/ZMACRDS_PATCH.md)在按钮前投递坐标，覆盖 fast-path / slow-path，并保留滚轮的独立语义。修复后客户端点击、跨窗和拖选通过。
4. 直接通过桌面自动化向 Windows App 发送非拉丁 Unicode，以及 Shift 组合键，未得到可靠投递；当前不能据此宣称客户端直接中文或修饰键通过。改用真实服务端拼音完成了中文用例。
5. 一次后台窗口缩略图被误当成实际操作尺寸，重新激活后的点击误开了测试账号的日历，未输入到编辑器。重新获取前台完整尺寸并关闭日历后，点击和拼音通过。该次操作不计为缩放验收；不同窗口尺寸及 Retina 的完整矩阵仍待测。

真实桥接路径不更新动态图计数器，所以当前 `server-26b.jsonl` 的 `frames/key_down/...` 为 0；这些字段仅适用于动态图模式。本报告的真实输入和画面证据取自 GUI 代理、独立编辑器和客户端观察，不使用这些 0 值推断活动量。
