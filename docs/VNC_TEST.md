# VNC 主路线与验收

2026-11-04，依据用户在 VM03 的实际交互反馈，将 VNC 作为首版主路线，暂缓 RDP 扩展。项目目标仍为同一 Mac Server 上的独立多用户桌面，支持 Mac、Windows 以及混合客户端；32 人是容量目标，不是已验证能力。

## 已知状态

11 月 5 日实施进展见[改造回归](reports/REFACTOR_VM03_2026-11-05.md)：官方 TigerVNC macOS 构建已验证原生账号独立桌面；新增 VNC 账号网关已在 VM03 有界部署。网关运行说明、固定分辨率 RDP 配置和打包方法见 [VNC_GATEWAY.md](VNC_GATEWAY.md)。最终 Mac/VM03 双账号 1830 秒、每侧 100 轮跨应用/中文/拖选已通过，应用日志逐轮复核一致；接管、错误口令和慢接收端故障通过。Windows、锁屏/注销与更高容量仍未测。

- 苹果屏幕共享已进入 VM03 的独立 vnc 用户桌面，并与 VirtualBuddy 控制台用户、RDP 用户同时保持登录，三侧输入归属已核对。见[记录](reports/VM03_THREE_USERS_2026-11-04.md)。这不是三个 VNC 客户端的并发验证。
- 历史 RDP 实验有明显交互体验问题，用户报告连接窗口突然断开。Windows App 主进程、来宾代理和服务端持续运行；服务日志显示连接约 348 秒后正常返回，尚无充分证据判断触发原因。重连恢复原桌面。这条历史失败保留；11 月 5 日改造后固定远端尺寸的 48 次窗口缩放通过，动态远端尺寸仍不支持。
- RDP 采集目标 30 FPS 不代表实际达到 30 FPS。先前约 2 FPS 基线与后续功能检查不能作为优化后的性能验收。
- Windows VNC 尚未连接实测。TigerVNC 官方提供 Windows 安装包和 macOS 客户端，可作为候选；支持 VNC 和账号认证不自动证明能选择独立 Aqua 会话。[官方项目](https://tigervnc.org/)；[发行说明](https://github.com/TigerVNC/tigervnc/releases)。

## 验收矩阵与后续顺序

1. **先验证第三方客户端的会话归属**。先在可用 Mac 上使用跨平台 VNC 客户端验证 Apple 账号登录、桌面选择和后台输入，再在实际 Windows 客户端重复。每次核对 UID、GUI UID、Aqua 审计会话及独特编辑器文本；仅看见登录页或当前控制台不算通过。若原生服务无法向第三方客户端提供独立会话，再评估每用户 VNC 代理与统一入口，不能用所有人共享控制台代替。
2. **同用户恢复与接管**。A 断线后从 Mac/Windows 回到同一桌面；新 A 连接接管旧控制端，旧端失去输入能力，B 不受影响。先记录原生 VNC 的实际行为；若原生服务允许同用户共享控制，须实现并验证项目要求的接管策略。
3. **交互与稳定性**。两侧连续打字、滚动、移动窗口，验证中文、修饰键、缩放及坐标。单独记录窗口关闭、进程崩溃、连接断开与代理退出，保留退出原因。登录成功不能代替可用性验收。
4. **跨平台并发矩阵**。Mac/Mac、Windows/Windows、Mac/Windows 各用两个不同账号操作 30 分钟；每侧 100 次输入、点击及拖动，后台输入不切换控制台，不串桌面。覆盖一侧重连、锁屏、注销与网络中断，另一侧持续可用。
5. **容量**。依次测试 2、4、8、16、32 个独立账号。VM03 保持用户指定的 4 核、8 GB，不把测试机进程资源耗尽误归为协议限制。只发布实测通过的硬件、人数与客户端组合。

## 统一通过条件

局域网首轮目标为 1080p、滚动有效刷新至少 15 FPS、输入到画面更新 p95 小于 200 ms；记录实际客户端版本、编码、安全模式、CPU、内存、网络吞吐和意外断连次数。VNC 与 RDP 的对比须固定分辨率、负载和测量方法。

初期沿用当前回环监听和 SSH 转发，不为了兼容客户端改成共享弱口令或直接开放来宾网络端口。Windows 客户端必须验证实际传输保护，不能把账号密码的加密误当作整条画面与输入流已加密。

在上述客户端矩阵、隔离、接管和性能均通过前，不宣称跨平台多用户 VNC 首版完成。冷启动创建图形会话、系统账号管理、持久化服务及故障自动恢复仍须单独验收。
