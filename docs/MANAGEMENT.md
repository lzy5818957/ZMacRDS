# 后台代理与管理窗口

常驻安装后，用户桌面不再显示 M1 的彩色诊断窗口。各账号菜单栏显示 **ZMacRDS**，可以查看连接及权限状态、断开本账号的 RDP、打开管理窗口或系统设置。正常启动不抢走当前应用的输入焦点，也不自动弹出辅助功能授权提示。

在服务器自己的图形桌面打开 `/Applications/ZMacRDS Manager.app`，或选择菜单栏的“打开管理窗口”。管理窗口列出桌面代理、录屏与键鼠权限、RDP 连接和采集状态。VNC 是 macOS 原生屏幕共享，窗口里的连接状态与断开按钮只针对本项目的 RDP。

## 安装和升级

按 [常驻服务](SERVICE.md)准备私有配置和稳定签名的构建，安装时同时提供管理程序和控制服务：

```sh
sudo python3 tools/install-service.py \
  --config /private/test/server.json \
  --app './ZMacRDS-Desktop.app' \
  --server './zmacrds-rdp-probe' \
  --launcher './tools/start-desktop' \
  --controller './zmacrds-control' \
  --manager './ZMacRDS-Manager.app'
```

两个新增参数必须成对提供。安装器先验证应用和管理程序的签名、读取所需构建和证书，再停止已有服务；缺少文件或签名无效的更新不会先停掉正在工作的服务。安装会中断现有 RDP，用户的桌面应用保留。管理窗口需要 macOS 图形桌面，不通过网络暴露管理接口。

桌面程序保持 `org.zmacrds.desktop` 的 bundle ID 和签名身份。新账号仍需先建立 Aqua 登录会话，并在本账号内授予录屏及辅助功能权限。管理窗口不会自动登录新用户、绕过锁屏或替用户批准系统隐私权限。

## 常见操作

| 操作 | 结果 |
| --- | --- |
| 断开所选账号的 RDP | 关闭该账号当前 RDP 传输，释放按键和声音采集；保留桌面代理与应用，可重新连接 |
| 停止桌面代理 | 卸载该账号的 launchd 任务，停止其 RDP 采集与输入；不注销用户、不关闭用户应用 |
| 启动桌面代理 | 在该账号已经登录的图形会话重新装载任务 |
| 重启桌面代理 | 重建本账号代理；该账号的 RDP 需要重新连接 |
| 停止／重启服务 | 中断全部 RDP；图形桌面及原生 VNC 保留 |
| 锁定管理／关闭窗口 | 撤销该窗口持有的管理员验证 |

普通用户只能看到和操作自己加入服务的账号。管理员账号可查看已配置账号，但管理其他账号或系统服务仍需要系统的管理员验证。普通用户完成同样的管理员验证后也可临时管理这些固定操作。验证最多保留五分钟；窗口可主动锁定，关闭窗口会撤销验证。程序不接收或保存管理员密码，密码由 macOS 自己的验证窗口处理。

“采集暂停”表示系统暂未提供可用画面，仍需正常唤醒或解锁；“等待代理报告”不能作为已授权或已连接的证据。权限需要在对应账号内处理。重启代理不会撤销已正常授予的权限，但更换签名可能触发系统重新授权。

## 本机控制边界

`/Library/LaunchDaemons/org.zmacrds.control.plist` 启动 root 控制服务；客户端只通过 `/var/run/org.zmacrds.control.sock` 通信。客户端核对服务端是 root，服务端从内核取得调用者 UID，只接受固定动作和已配置的 UID，不接受命令、程序路径或客户端声称的用户名。请求最多 8 KiB，整条请求读取最多三秒，工作队列有上限。

系统或其他账号操作使用独立的 `org.zmacrds.manage` Authorization Services 权限，不修改系统通用的管理员规则。凭证只在管理窗口内存和本机 IPC 中短暂使用，不写入配置或日志。服务端验证时不弹密码框。管理员可自行定制该权限；安装器保留自定义规则。

用户代理的启动先进入对应图形会话并降为该 UID，再读取其用户 LaunchAgent。用户即使修改自己的任务文件，也不能借管理入口以 root 执行它。网络服务只使用固定的 root 文件。

断开指令由 root 写入固定目录，以 ACL 只允许目标账号读取；它绑定 UID、代理随机代次、审计会话及本次系统启动，十五秒后失效。代理只接受一次，不会在重连后再次踢掉新连接。状态回复仅包含列出的运行及权限字段，不导出网络口令、文档、桌面像素或按键文字。

管理员可用以下固定命令检查；普通用户不加 sudo 只能操作自己的账号：

```sh
/usr/local/libexec/zmacrds-control --client status
/usr/local/libexec/zmacrds-control --client disconnect-rdp 505
sudo /usr/local/libexec/zmacrds-control --client restart-agent 505
sudo /usr/local/libexec/zmacrds-control --client restart-server
```

## 采集与诊断

后台代理保留一个本进程的透明 8×8 窗口，用它确认所属显示器；只允许恰好一个显示器与该窗口匹配。采集时排除这个窗口，不会显示彩色诊断内容，也不会为了测试计数器制造桌面变化。身份匹配失败时不回落到控制台或其他用户显示器。多显示器及无头配置仍需单独验收。

原来的限时 M1 诊断模式保持可用。实际输入回归需要当前测试编辑器的可辨认回执，不能再用后台代理本身作为像素标记。检查器的 `service_probe: true` 只检查连接持续、收到初始桌面，允许画面完全静止，且禁止输入、音频或动态图测量；它不证明桌面内容属于哪个用户。用户隔离应结合固定 UID 绑定、带独立标记的测试窗口和实际收到的文档内容验证。

VM03 的具体结果和范围见[后台与管理窗口报告](reports/BACKGROUND_MANAGER_2026-11-05.md)。

检查器还可在被动模式设置 `frame_summary: true`，输出少量采样行的主要颜色及比例，用于定位整片缺画面的情况；不保存图片。它只能检查受控测试桌面的绘制特征，不能据此证明像素与源完全一致。

桌面代理把有效采集帧复制到自己的像素缓冲后再缓存，不长期占用 ScreenCaptureKit 的系统表面队列。有效 Idle 样本可维持静止桌面的存活；Blank／Suspended／Stopped、权限或会话失效仍会清除画面与输入。传输停顿后，服务主动请求绑定现有连接的恢复确认和完整帧；停顿前排队的旧确认与按键不能恢复输入。

本环境的后台虚拟显示器静止时曾停止产生回调。macOS14及以后，代理在已建立有效基线、采集仍运行且约一秒没有回调时，通过相同账号的精确显示过滤器请求一次真实单帧采集，最多每两秒一次。请求的返回画面直接丢弃；它不刷新存活时间，不恢复输入。后续正常流样本仍必须通过原有身份、状态与时间戳检查。显式暂停或等待恢复证明时不使用此请求；失败仍由原有暂停和有界恢复路径处理。

RDP 默认使用兼容编码策略。NSCodec 目前仅在服务环境显式设置 `ZMACRDS_EXPERIMENTAL_NSCODEC=1` 时开放；Windows App 未选择 RemoteFX 时回退到原始 SurfaceBits。原始传输耗带宽较高，不能把本机可用性等同于公网性能验收。远端分辨率仍固定，客户端窗口缩放不代表支持动态远端分辨率。
