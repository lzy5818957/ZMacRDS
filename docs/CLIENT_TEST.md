# Mac / Windows 客户端兼容与并发验收

**当前优先级（2026-11-04）**：首版改用 VNC 主路线，当前验收见 [VNC_TEST.md](VNC_TEST.md)。下文为保留的 RDP 专项计划和历史结果，不能用于宣称当前交互体验已达标。同用户新连接需求已改为接管原控制端，历史的重复登录拒绝条目不再是当前目标。

11 月 5 日构建使用[固定远端分辨率配置](../config/ZMacRDS-fixed.rdp)，关闭 Windows App 的 “Update the session resolution on resize”，保留 “Fit session to window”。目前仅支持固定远端几何的客户端缩放；动态分辨率不能作为已实现能力。当前回归结果见[报告](reports/REFACTOR_VM03_2026-11-05.md)。

本文件定义 M2–M4 的交付要求。macOS Windows App 已完成单账号真实桌面的部分 M2 验证，并已在 VM03 同一入口建立 A/B 双连接；完整 M2、M3 与 M4 均未通过。M0/M1 的本地实验不能代替两种 RDP 客户端及多用户并发验收。

## 支持目标

服务端为同一台 Mac 上的 ZMacRDS。用户从 Mac 或 Windows 客户端连接同一个服务器地址和端口，以各自身份获得独立的 macOS 桌面，画面、键鼠与应用会话按用户隔离。32 人是两种客户端合计的并发目标。

| 客户端系统 | 首版验收客户端 | 连接方式 | 当前状态 |
| --- | --- | --- | --- |
| Windows 11 | 自带远程桌面连接 `mstsc.exe` | 输入服务器地址并使用用户凭据连接 | 待实现、待实测 |
| macOS | Microsoft Windows App | 使用 Add PC 添加同一服务器地址并使用用户凭据连接 | 单账号画面、点击/拖选、拼音与重连已测；同入口 A/B 双连接已测；完整矩阵待测 |

Microsoft 的[连接文档](https://learn.microsoft.com/en-us/windows-app/get-started-connect-devices-desktops-apps?pivots=remote-pc&tabs=macos-pc)提供 macOS Windows App 的 Add PC 入口。该文档说明客户端用法；与 ZMacRDS 自定义服务端的兼容性需按下列用例验证。测试记录必须包含客户端系统构建与应用版本，最终支持范围以实际通过的版本为准。

首版复用这两个 RDP 客户端。服务端按每条连接实际协商到的能力工作，不能因为一个客户端改变分辨率、输入模式或编码能力而改变其他用户的连接。

## 已准备的客户端环境

2026-11-04 已在宿主 Mac 打开 Windows App，确认可进入 Devices 界面；About 显示版本为 **11.4.4 (3132)**。宿主系统为 **macOS 27.2 (26B123)**，后续 Mac 端 RDP 测试使用此客户端，测试前重新记录实际版本。

随后使用实验 RDP 服务端完成了协议动态图和 VM03 A 账号的真实桌面连接。服务端在 VM03 的 `127.0.0.1:3390` 监听，宿主通过 SSH 回环转发访问；未开放 LAN 端口。实测尺寸为 1920×1200、2 fps 配置。Windows App 的 Scancode 模式配合服务端简体拼音提交了“你好世界测试”；跨窗口点击、拖选和 RDP 重连保留编辑器/文本也通过。

M2 的单用户历史结果见 [M2 实测报告](reports/M2_VM03_2026-11-04.md)。随后新增 `--multi`：独立随机测试凭据分别固定绑定预先登录的 A/B UID；入口进程降权，每个 UID 使用独立 relay。Windows App 在同一宿主开启两条同地址连接，已验证后台输入、中文、A 断线重连保留编辑器和 B 持续工作，以及 A 代理停顿的故障隔离。该历史构建对错误口令、交叉口令和重复登录都返回明确拒绝。后续版本改为正确凭据接管同一账号的原桌面，缺失凭据的独立画面门槛有单元测试。详见 [M3 实验报告](reports/M3_VM03_2026-11-04.md)。

上述不是系统账号认证。Windows App 使用用户授权的短期自签名证书例外，没有保存永久信任；自动客户端使用局部证书信任及精确叶证书 pin。完整修饰键、网络黑洞、锁屏、撤权和新会话自动注册仍需覆盖。

## M2 · 两端分别可用

先对动态测试图执行协议验证，再对通过 M1 的真实用户代理重复操作。两种客户端分别完成以下检查。

1. 使用受信任的测试证书连接，验证服务器身份并记录实际安全模式。有效凭据只能进入对应账号；无效凭据不得收到桌面画面或发送输入。
2. 连续显示计数器，确认持续刷新；在 1920 × 1080 基线和客户端高 DPI / Retina 缩放下分别验证点击位置、窗口边缘拖动与滚动。改变窗口或全屏状态后，记录实际远程分辨率和坐标映射。若未协商动态分辨率，保持已协商尺寸并正确缩放，不得坐标错位。
3. 验证 Shift、Control、Option / Alt、Command / Windows 键、组合键、按下与释放；记录客户端设置和实际送到 macOS 的键义。测试失焦、断线以及重连后无卡住的修饰键，且不影响其他会话。
4. 分别输入可辨认的英文、数字、符号和中文，记录使用服务端输入法还是客户端 Unicode 输入，核对收到的内容和组合输入行为。
5. 断开并用同平台客户端重连，保留原窗口和未保存的测试文本，核对仍为原账号和会话。

## M3 · 并发矩阵

M0、M1 及两端 M2 都通过后，使用两个不同的普通 macOS 测试账号 A、B，保持两个真实 Aqua 会话同时登录。每行使用两个独立客户端连接同一个 Server，各运行至少 30 分钟，并执行[双用户实验操作单](DEVELOPMENT_PLAN.md#双用户实验操作单)的全部隔离检查。

| 用例 | A 的客户端 | B 的客户端 | 必须保留的结果 | 状态 |
| --- | --- | --- | --- | --- |
| C-WW | Windows / mstsc | Windows / mstsc | 两个独立桌面持续刷新、输入无错投、恢复互不影响 | 待测 |
| C-MM | macOS / Windows App | macOS / Windows App | 两个独立桌面持续刷新、输入无错投、恢复互不影响 | 同一宿主双连接部分通过；两台客户端及完整工作负载待测 |
| C-WM | Windows / mstsc | macOS / Windows App | 两个独立桌面持续刷新、输入无错投、恢复互不影响 | 待测 |

每行还需验证：

1. A、B 使用不同颜色和随机标记，分别完成各 100 次输入、点击和拖动。轮换服务端前台账号，后台用户的画面与输入仍可用；远程操作不得切换本机前台用户。
2. A 改变客户端窗口、缩放或协商分辨率，B 的画面、坐标映射与输入不改变。交换 A、B 重测。
3. A 断开并从另一平台重连，核对服务端 UID、会话代次、测试窗口和未保存文本均保留，B 连续工作。两个方向 Windows → Mac、Mac → Windows 均须覆盖。
4. A 仍连接时，以同一身份再次正确登录，接管并关闭旧 A 的控制端，原桌面和文档保留，B 继续工作。错误口令不得踢掉 A；模拟旧 A 网络中断后由新 A 接管，旧端复网不能再次输入。两个平台的接管方向分别实测。
5. 注销 A、撤销 A 的录屏权限或使 A 的代理退出，B 保持可用，A 的连接不得回落到 B 或控制台桌面。A 重新登录后应建立新会话代次，旧代理与旧连接不能重新获得控制权。
6. A、B 各自在独立工作目录中用 Codex 完成一个可辨认的小任务，记录人工与 Computer Use 操作。保留合成测试内容，避免采集真实工作资料。

## 结果记录与通过标准

每次测试填写以下信息，原始证据存放在访问受限的测试结果目录，不把凭据或真实桌面内容写入版本库。

| 记录项 | 内容 |
| --- | --- |
| 实验 | 日期、实验编号、项目提交、M2 / M3 / M4、用例编号 |
| 服务端 | 机型或虚拟机配置、macOS 构建、显示配置、账号短名与 UID、会话代次 |
| 客户端 | 两端系统构建、应用名称与版本、键盘布局、输入法、缩放及客户端设置 |
| 连接 | 服务器测试地址、实际安全模式、协商能力、分辨率、连接和重连时间 |
| 隔离 | 帧更新时间、两侧操作次数、错投次数、前台是否被切换、故障与复现步骤 |
| 结论 | PASS / FAIL / 未测，原始记录路径；未完成的步骤与限制 |

只有两种客户端各自通过 M2 且三种组合全部通过 M3，才能宣称首版支持 Mac / Windows 多用户并发。画面串流到其他账号、输入错投或后台桌面不可用均判为失败；未执行的用例标为未测。

M4 按[开发计划](DEVELOPMENT_PLAN.md#容量测试与决策)逐档执行 2、4、8、16、32 人混合负载。双用户通过仅证明已测组合的双用户能力，不能推断 32 人容量或未测试客户端版本的兼容性。
